## Project Overview

This is a personal website/blog built with **Astro 5** and deployed to **Cloudflare Workers**. It is based on the Astro Blog starter template and is configured for static site generation with edge delivery via Cloudflare.

- **Framework**: Astro 5.16.2
- **Language**: TypeScript (strict mode)
- **Deployment**: Cloudflare Workers via `@astrojs/cloudflare` adapter
- **Content**: Markdown and MDX blog posts via Astro Content Collections

## Development Commands

```bash
npm run dev        # Start local dev server at http://localhost:4321
npm run build      # Build production site to ./dist/
npm run preview    # Build + preview locally with Wrangler (Cloudflare Workers emulation)
npm run check      # Full check: build + TypeScript + Wrangler dry-run deploy
npm run deploy     # Deploy to Cloudflare Workers
npm run cf-typegen # Regenerate Cloudflare Worker type definitions (worker-configuration.d.ts)
```

Always run `npm run check` before deploying — it runs `astro build && tsc && wrangler deploy --dry-run` to catch build, type, and deployment errors together.

## Content Collections (Blog)

Blog posts live in `src/content/blog/` as `.md` or `.mdx` files. Each post requires this frontmatter (validated by Zod at build time):

```yaml
---
title: "Post Title"          # required string
description: "Short summary" # required string
pubDate: "2024-01-15"        # required, coerced to Date
updatedDate: "2024-02-01"    # optional, coerced to Date
heroImage: "/path/to/image"  # optional string
---
```

The content collection is defined in `src/content.config.ts`. Missing required fields or wrong types will cause build errors.

## Coding Conventions

### Naming
- **Components**: PascalCase with `.astro` extension (`BaseHead.astro`, `BlogPost.astro`)
- **Pages**: kebab-case for slugs and file names (`blog/[...slug].astro`)
- **Content files**: kebab-case (`first-post.md`, `markdown-style-guide.md`)
- **Variables/props**: camelCase (`heroImage`, `pubDate`, `updatedDate`)
- **CSS classes**: kebab-case (`sr-only`, `social-links`)
- **Constants**: SCREAMING_SNAKE_CASE (`SITE_TITLE`, `SITE_DESCRIPTION`)

### Imports
- Use relative paths for local components: `import BaseHead from '../components/BaseHead.astro'`
- Use Astro virtual modules for content: `import { getCollection } from 'astro:content'`
- Import constants from `src/consts.ts`

### Styling
- **No CSS framework** — vanilla CSS with CSS custom properties
- Global CSS variables defined in `src/styles/global.css`:
  - `--accent: #2337ff` — primary blue accent
  - `--black: 15, 18, 25` — base dark color
  - `--gray-*` — grayscale palette
  - `--box-shadow` — standard shadow utility
- Scoped styles live in `<style>` blocks inside `.astro` files
- Single responsive breakpoint at **720px**
- Font: **Atkinson** (woff format, regular + bold), preloaded in `BaseHead.astro`
- Accessibility: use `.sr-only` for screen-reader-only content

### TypeScript
- Strict mode is on (`astro/tsconfigs/strict`, `strictNullChecks: true`)
- Cloudflare runtime types are defined via `worker-configuration.d.ts` (auto-generated by `npm run cf-typegen`)
- `App.Locals` extends the Cloudflare `Runtime` type in `src/env.d.ts`

## Site Configuration

Update these before going live:

1. **Site URL** — change `site: "https://example.com"` in `astro.config.mjs` to the real domain
2. **Site title & description** — edit `SITE_TITLE` and `SITE_DESCRIPTION` in `src/consts.ts`
3. **Social links** — update Mastodon, Twitter, and GitHub URLs in `src/components/Header.astro` and `src/components/Footer.astro`
4. **About page** — replace Lorem ipsum in `src/pages/about.astro`
5. **Favicon** — replace `public/favicon.svg`

## Deployment

The site deploys to Cloudflare Workers via Wrangler:

```bash
npm run deploy   # runs: wrangler deploy
```

The build output (`./dist/`) is configured as a static asset directory in `wrangler.json`. The Cloudflare adapter bundles the worker entry point at `./dist/_worker.js/index.js`.

- Observability logging is enabled in `wrangler.json`
- Source maps are uploaded for production debugging (`upload_source_maps: true`)
- Compatibility date: `2025-10-08` with `nodejs_compat` flag

## Adding New Blog Posts

1. Create a new `.md` or `.mdx` file in `src/content/blog/`
2. Add required frontmatter (`title`, `description`, `pubDate`)
3. Write content below the frontmatter delimiter
4. Run `npm run dev` to preview, then `npm run check` before deploying

## Adding New Pages

1. Create a new `.astro` file in `src/pages/`
2. Import `BaseHead` for SEO metadata and `Header`/`Footer` for consistent layout
3. The file path determines the route (e.g., `src/pages/projects.astro` → `/projects`)
